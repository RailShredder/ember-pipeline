# 3D→2D 精灵管线技术路径

> 状态：已定稿（v1） · 日期：2026-09-28 · 结论有效期：约半年，3D 生成赛道迭代快，到期需复核
>
> 适用范围：ember 的角色、敌人、boss 等需要骨骼动画的动态资产。静态道具图标仍走现有 LoRA 直出管线（见 `prompts/item.md`）。

## 0. 一句话结论

美术与动画全部在 3D 里制作，逐帧渲染成 2D 精灵后在 Godot 里当纯 2D 播放（死亡细胞 / 哈迪斯路线）。
生成环节用 5080 本地跑开源模型（TripoSG 主力），绑定动画用 Mixamo，渲帧用 Blender，**全链路零订阅成本**。

## 1. 为什么走 3D→2D 而不是纯 2D 生成

- **可控性**：3D 资产是确定性的——相机灯光锁死后渲一万次都一致。AI 视频生成给不了透明通道、帧间一致性、精确循环和"第 N 帧手举到最高点"这类对齐攻击判定的控制（这正是两家标杆 studio 不用视频直出的原因）。
- **动画产能**：3D 动画可调速、加缓动、做挤压拉伸，改 pose 不用重画；骨骼动画库可跨角色复用（换皮出新敌人成本低）。
- **运行时便宜**：引擎里只是播图片序列，无蒙皮无实时 3D 渲染。
- **比例稳定**：任何动作、角度下角色比例不崩。

标杆参考：
- **死亡细胞**（Motion Twin）：3ds Max 建模动画 → toon shader 自动批量出图，几乎无手工修帧，高帧数高产能；并**把法线烘进精灵**实现 2D 画面受动态光照。
- **哈迪斯**（Supergiant）：3D 建模动画 → 渲染出底稿 → 主美 Photoshop 手绘覆盖，插画质感，产能低但美术上限高。
- ember 起步阶段走死亡细胞路线（自动化优先），哈迪斯式的手绘覆盖作为后期美术升级预留的选项。

## 2. 全链路总览

```
ember LoRA 概念图（现有基建，图生3D 输入用单张正面直立图）
  → 3D 生成：TripoSG / Hunyuan3D 2.1（5080 本地，只出形状，跳过 AI 贴图）
  → 绑定：标准人形走 Mixamo（免费）；非人形走 UniRig（开源）
  → 动画：Mixamo 动画库优先 → 海螺视频做动作参考 → Blender 手 K 兜底
  → 渲帧：Blender EEVEE + toon shader，锁定正交相机与灯光，按 12/24fps 步长逐帧出 PNG
  → Godot：PNG 序列自动生成 SpriteFrames，AnimatedSprite2D 播放，帧号挂攻击判定/音效
```

## 3. 各环节选型与理由

### 3.1 概念图
沿用现有 `lora/` + `workflows/` 基建。角色设定需满足"管线友好"约束（见 §6 角色设定规范），出图用**单张正面、中性直立、白底**——图生 3D 最稳的输入，比一张三视图更可靠。

### 3.2 3D 生成（核心决策：本地开源，跳过贴图）

| 方案 | 定位 |
|---|---|
| **TripoSG（开源，主力）** | 网格几何质量为开源最佳，显存 ~8GB+，5080 宽裕 |
| Hunyuan3D 2.1 仅形状 | 备用，~10GB；生态最全（ComfyUI 节点多），可对比择优 |
| Hunyuan3D 完整贴图流程 | **不做**——需 ~29GB 显存，且贴图到了 toon 渲染阶段会被色阶化盖掉，投入无意义 |
| Tripo 云端（约 $19.9/月 Pro） | 仅作质量对比/应急，不订阅。免费额度（约 200 积分/月 ≈ 8 模型）够验证 |
| TRELLIS.2 | 观望，16GB 为及格线，暂不入产线 |

**关键判断**：本管线的终点是 toon 渲染精灵，需要的是好形体好剪影，不是 PBR 贴图。砍掉最重、最容易出问题的贴图阶段后，16GB 显存绰绰有余。

### 3.3 绑定
- **Mixamo（Adobe，免费）**：标准人形自动绑定 + 数百个现成动画（idle/run/attack/hurt/death 全覆盖），retarget 即用，可能一个动作都不用手 K。限制：仅标准双足人形；仅网页版，动画下载后本地留档，不当永久基础设施。
- **UniRig（开源）**：非人形（四足、多肢体）用，有 ComfyUI 节点。成本约为人形的 3 倍（手 K 动画），初期只给 boss 级内容用。

### 3.4 动画
优先级：Mixamo 库挑现成 → 缺的动作 Blender 手 K → 海螺（MiniMax 会员已有）图生视频做**动作参考**（验证"这个设计动起来成不成立"、替代翻找参考片）。注意：海螺只做参考与预览，不产出任何进游戏的内容。

### 3.5 渲帧（Blender，需在 Mac 上安装）
- EEVEE 渲染；toon 着色用 `Shader to RGB + ColorRamp` 色阶化，描边用 Solidify（翻转法线黑面）或 Grease Pencil；
- **正交相机 + 灯光全程锁定**，否则帧间闪动；
- 导出步长 12–24fps（够用且控制图集体积），PNG 带透明通道；
- 批量渲染用 Blender Python API 写脚本（遍历帧 → 出 PNG）。

### 3.6 引擎接入（Godot）
- PNG 序列拖入 Godot 4 自动生成 `SpriteFrames` → `AnimatedSprite2D` 播放；
- 帧事件在 AnimationPlayer 对齐帧号挂调用点（攻击判定生效帧、脚步声、受击帧）；
- **进阶项（M4）**：学死亡细胞把法线烘进精灵（表面法线作为颜色渲第二遍），Godot 侧 `Sprite2D + 法线贴图 + PointLight2D` 实现 2D 精灵受动态光照。

## 4. 硬件与预算

### 5080（16GB，Blackwell）适配结论：能跑，宽裕
| 模型 | 显存 | 5080 |
|---|---|---|
| TripoSG 全流程 | ~8GB+ | ✅ 宽裕 |
| Hunyuan3D 2.1 仅形状 | ~10GB | ✅ |
| Hunyuan3D 形状+贴图 | ~29GB | ❌ 不做（决策见 §3.2） |
| TRELLIS | 16GB 起步 | ✅ 及格线 |

### 环境要求（50 系专属，务必注意）
- PyTorch ≥ 2.7.0 且为 **cu128** 版本（2025-04 起原生支持 Blackwell sm_120）；
- NVIDIA 驱动 ≥ 570；
- 遇 `sm_120 is not compatible` 报错 = PyTorch 太旧，换 cu128 轮子，勿用老整合包；
- 推荐直接上 ComfyUI + ComfyUI-3D-Pack（Hunyuan3D/TripoSG/TRELLIS 全有节点）；不想折腾环境可用开源桌面应用 Modly 过渡。

### 成本账
| 环节 | 工具 | 花费 |
|---|---|---|
| 概念图 | 现有 LoRA + 5080 | 0 |
| 3D 生成 | TripoSG / Hunyuan3D 本地 | 0（电费） |
| 绑定+动画 | Mixamo | 0 |
| 非人形绑定 | UniRig | 0 |
| 渲帧 | Blender | 0 |

## 5. 约束与风险

| 风险/约束 | 影响 | 对策 |
|---|---|---|
| AI 生成网格是三角面汤，无干净布线 | 蒙皮动画关节处可能轻微破面 | 终点是渲 2D 帧，小瑕疵不可见；不投入重拓扑（除非个别角色破面明显，单独处理） |
| Mixamo 仅标准人形 | 换装/异形怪不适用 | 非人形走 UniRig + 手 K；比例夸张靠缩放骨骼，结构保持标准双足 |
| Adobe 条款禁止用其资产训 ML | 不能拿 Mixamo 动画渲出的帧回训 LoRA | 训练集用自 K 动画渲帧或 CC0 动捕库 |
| Mixamo 是纯网页服务 | 依赖 Adobe 服务器存续 | 所有下载的动画本地留档入库 |
| 3D 生成赛道迭代快 | 本文选型半年内可能过时 | 状态行标注有效期，到期复核；`lora/VERSIONS.md` 制度同款思路 |
| 左右镜像翻转角色 | 不对称细节（持握手性、单肩甲）露馅 | 设定阶段记录不对称件清单，渲帧时分别出左右帧或接受镜像 |

## 6. 角色设定规范（进产线的前置门槛）

原则：精灵在屏幕上仅 40–120px 高、0.3s 划过——设定要**认得出（剪影）、动得了（可动画）、产得出（管线友好）**。

1. **剪影第一**：定稿前做剪影测试（填黑）+ 缩小测试（缩到游戏实际像素高）。可存活特征 ≤3：一个体型 + 一个武器 + 一个头部特征。
2. **色彩签名**：每角色从 `style/palette.json` 锁 1 主色 + 1 辅色，LoRA 出图与 toon 渲染共用，颜色即玩法信息（哈迪斯式：看弹幕色知来源）。
3. **一个可动的记忆点部件**：飘带/披风/火焰/链——随动作摆动，每帧剪影都活着。静止图案在精灵尺寸下不可见。
4. **五个锚点动作**：idle / 移动 / 攻击 / 受击 / 死亡，设定阶段想清楚（对应 Mixamo 库标准集）。

**管线规避清单**（设计定稿前逐项检查）：
- [ ] 四肢末端可见（Mixamo 放标记点需要）
- [ ] 标准双足人形结构（比例可夸张）
- [ ] 无细链条/发丝/悬空小件（3D 重建丢失）
- [ ] 武器与手分离，可独立换装部件
- [ ] 无半透明/发光材质设定（发光在 toon/引擎 shader 阶段加）
- [ ] 无密集贴身图案（toon 色阶化后变噪点）

配套待建：`prompts/character.md`（角色出图模板，与 `item.md` 同风格）+ 角色设定卡模板。

## 7. 落地里程碑

| 阶段 | 内容 | 完成标志 |
|---|---|---|
| M1 环境 | 5080 机装 ComfyUI + 3D-Pack（TripoSG 可用）；Mac 装 Blender | 各出一版测试资产 |
